# http: API 호출 예시 (IntelliJ HTTP 클라이언트)

`.http` 파일을 열면 요청마다 ▶ 버튼이 생기고, 눌러서 바로 호출할 수 있습니다.
Swagger는 한 건씩 호출하고, 이 파일은 신청 → 승인 → 완료처럼 **여러 요청을 순서대로 이어서** 확인할 때 씁니다.

## 규칙
- 도메인마다 파일을 하나씩 둡니다. (`adoption.http`, `cat.http`, `post.http` ...) 자기 도메인 파일만 고칩니다.
- 구현이 끝난 API는 그대로 실행되게 두고, **아직 구현하지 않은 API**는 파일 맨 아래에 `### [미구현]`을 붙여 두되 **요청은 주석(`#`)으로 막아 둡니다.** 구현이 끝나면 주석을 풀고 `[미구현]` 표시를 지웁니다. (API 목록은 명세서와 README의 구현 현황 표를 따릅니다)
- 요청 제목(`###` 뒤)에 기대 결과를 적습니다. 예: `- 201`, `- 403`
- **토큰, 비밀번호, 실제 개인 정보는 넣지 않습니다.** (저장소가 공개입니다)
- 호스트 같은 환경값은 `http-client.env.json`에 둡니다. 파일에서는 `{{host}}`로 씁니다.

## 실행 방법
1. 서버를 띄웁니다.
2. 파일 오른쪽 위의 환경 선택에서 `local`을 고릅니다. (안 고르면 `'host' 변수가 대체되지 않았습니다` 오류가 납니다)
3. **`auth.http`를 먼저 위에서부터 실행**해서 토큰을 받습니다.
4. 다른 파일의 요청 옆 ▶ 버튼을 위에서부터 차례로 누릅니다. 응답 값을 변수에 저장하는 요청은 순서대로 실행해야 합니다.

## 인증
- API는 JWT로 인증합니다. 로그인이 필요한 요청에는 `Authorization: Bearer {{token1}}` 헤더를 붙입니다.
- `auth.http`를 실행하면 로그인 응답의 Access Token이 `token1`(tester), `token2`(tester2), `token3`(tester3)에 저장되고, 다른 http 파일에서도 그대로 쓸 수 있습니다.
- 토큰은 실행할 때 IntelliJ에만 저장되고 파일에는 남지 않습니다. 파일에 토큰 값을 직접 적지 않습니다.
- Access Token은 30분 뒤 만료됩니다. 401 `TOKEN_EXPIRED`가 나오면 `auth.http`의 로그인을 다시 실행합니다.
- 예전 `X-Dev-Member-Id` 헤더는 더 이상 통하지 않습니다. 쓰던 파일은 위 헤더로 바꿉니다.
